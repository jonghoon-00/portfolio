### 3-1) 쿠폰 시스템 구현

<CldImage src="v1763460174/%EC%BF%A0%ED%8F%B0_pdwodh.gif" alt="쿠폰 흐름 gif" />

장바구니 쿠폰 적용 > 결제 페이지 이동(상태 유지)

**구현 내용**

- **사용자 쿠폰 리스트 및 적용 기능 구현**
- 초기 MVP의 단순 할인 로직을 **DB 쿠폰 테이블 기반 처리로 확장**
- **클라이언트 쿠폰 계산 로직 > 서버 계산 리팩토링**으로 보안 및 신뢰성 강화

**기술적 접근**

초기 MVP 단계에서는 단순한 형태의 할인 기능만 존재했지만, 구조 확장을 위하여 쿠폰 DB를 생성한 후 서버측에서 금액을 계산하도록 수정하여 보안을 강화했습니다.

- 쿠폰을 단순 상태값이 아닌 독립적인 DB 테이블로 분리하여 확장성 확보
- 서버(Route Handler)를 통한 할인 금액 계산으로 위변조 가능성 최소화
- 사용자 정보와 쿠폰 간 참조 관계 구조화

### 3. 결제 플로우 전체 담당

![결제(2).gif](<attachment:9f1d9315-b1a1-40e5-99af-405ec5f9f369:결제(2).gif>)

**구현 내용**

- `/payment` → `/check-payment` → `/complete-payment` 전체 결제 흐름 구현
- 장바구니 내 **쿠폰 선택 및 적용 기능**을 결제 페이지와 연동
- 결제 페이지 **배송지 CRUD 및 선택 로직** 설계 및 구현
- API 연동을 통한 결제 트랜잭션 처리 및 주문 데이터 DB 저장
- **브라우저 뒤로 가기 시 결제창 잔존 문제 해결** (`popstate` 이벤트 활용)

**UX 개선**

사용자 테스트 중, 브라우저 뒤로 가기 버튼을 눌렀을 때 결제창이 남아있는 문제를 발견했습니다. 이 문제 해결 과정에서 `popstate` 제어 방식을 학습하며 QA 과정의 중요성을 체감했습니다.

### 4. 주문 내역 및 환불 관리

(gif 추가)

**구현 내용**

- `/pay-history` 페이지 구현: **날짜별 필터링, 환불, 리뷰 기능 통합**
- 가결제 자동 환불 감지용 **웹훅 연동**, **DB 상태 자동 동기화** 처리

**웹훅(Webhook) 도입**

결제 자동 취소(가결제) 내역이 실시간 반영되지 않는 문제를 해결하기 위해, 포트원 API 웹훅을 활용해 결제 취소 이벤트를 서버 라우트에서 처리했습니다. 데이터 흐름 검증 과정은 ngrok을 사용해 테스트 환경을 구성했습니다.

- 결제 취소 발생 시 주문 상태 업데이트와 사용 쿠폰 복구가 자동으로 처리되도록 시스템 개선

### 5. 공용 컴포넌트 설계

**구현 내용**

- 반응형 모달 컴포넌트 제작 (모바일 ↔ 데스크톱 전환 지원)
- 배송지 관리, 쿠폰 선택 등의 페이지에서 재사용성 확보 및 코드 일관화

**기술적 접근**

- 버튼, 모달, 아코디언, 라디오 그룹 등 자주 사용되는 UI 컴포넌트화
- 데스크탑에선 모달, 모바일에선 풀 화면으로 전환되는 공용 모달 구현
- 연속 클릭으로 인한 오류 방지를 위한 `useThrottle` 훅 제작
