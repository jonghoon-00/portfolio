# 1. [MVP]

## 1-1) **MVP 범위 정의 & 태스크 분해**

#### **MVP 목표**

게시글을 작성 → 위치 지정 → 상세에서 확인 → 댓글로 소통까지 끊기지 않는 메인 흐름을 완성

#### **포함한 범위 (1주 MVP)**

- 게시글 CRUD + 위치 데이터 저장/수정 플로우
- 댓글 CRUD
- 로그인 / 회원가입 / 마이페이지

#### **제외한 범위**

- 지도 중심 탐색 UX(다수 마커 상태/클러스터링/가상화)
- 실시간 기능(채팅/알림) 및 고도화된 검색/필터
- 예외 케이스 확장(복잡한 권한 시나리오, 오프라인 대응 등)

#### **태스크 분해 방식**

기능별 분해가 아닌,  
사용자 플로우 단위(수직 슬라이스)로 쪼개서 흐름에 따라 정의

## 1-2) 핵심 구현 및 판단

### 1. 지도 기반 게시글 표시 구조 설계

#### **문제 상황**

일반적인 지도 기반 서비스는 지도를 중심 화면으로 두고, 마커를 통해 게시글을 탐색하는 구조를 취합니다.  
그러나 1주라는 제한된 기간에서 이 구조는 마커 상태 관리, 선택된 게시글 동기화 등 복잡도를 빠르게 증가시킬 수 있다고 보았습니다.

#### **판단**

이번 프로젝트에서는 게시글 상세 화면 안에 지도를 포함하는 구조가 MVP 범위에 더 적합하다고 판단했습니다.

#### **해결**

- 게시글 중심 구조에서 지도를 보조 요소로 배치
- 게시글 상세 페이지에 지도 컴포넌트 임베드 및 데이터 연동 담당
  - 팀원이 만든 지도 컴포넌트를 활용
  - 게시글 CRUD와 지도 간 위치 데이터 동기화 로직 구현
- 게시글 수정 시 위치 변경 플로우 설계 및 구현
- 다수 마커 관리나 지도 탐색 기능은 MVP에서 제외

#### **결과**

- 게시글 → 지도 흐름이 명확한 단방향 구조 확보
- 지도 관련 상태 관리 최소화
- 제한된 기간 안에서도 안정적인 기능 완주 가능

<br />

### 2. 댓글 CRUD 및 사용자 경험 개선

#### **문제 상황**

댓글 작성·수정·삭제 시 응답 지연으로 화면에 즉각적으로 반영되지 않는 문제가 있었습니다.  
커뮤니티 서비스 특성상, 댓글 반영 속도는 UX 체감에 직접적인 영향을 준다고 판단했습니다.

#### **판단**

실시간 동기화나 복잡한 상태 공유보다는,  
**빠르게 사용자 반응성을 우선 확보하는 것**이 MVP 단계에 더 적절하다고 판단했습니다.

일관성보다 즉각적인 피드백을 우선시하는 방향을 선택했습니다.

#### **해결**

- React-Query의 `useMutation`과 `optimistic update` 적용
  - 서버 응답 전에 로컬 상태를 먼저 업데이트하여 즉각 반영
  - 서버 요청 실패 시 이전 상태로 자동 롤백
- 로딩 및 에러 상태를 UI에 명확히 노출
- 실패 시 롤백 처리로 사용자 혼란 최소화

#### **결과**

- 댓글 작성 시 즉각적인 화면 반영으로 체감 반응 속도 개선
- 서버 응답 지연(~2초) 상황에서도 사용자는 바로 결과 확인 가능
- 네트워크 에러 발생 시 자동 롤백으로 데이터 불일치 방지

# **2. [유지보수] 데모 운영 안정화**

> 해당 프로젝트를 **포트폴리오로 지속 가능한 데모**로 만들기 위한 과정

## 1. Supabase 무료 플랜 제약 → IndexedDB로 데모 데이터 계층 마이그레이션

#### **문제 상황**
- supabase **무료 플랜 제약**으로 기존 DB 일시정지 
- 언제든 실행 가능해야하는데, 외부 서비스에 의존시 안정성 저하

#### **판단**
- **외부 의존성을 최소화**해야한다.
- 향후 운영/확장 가능성을 염두하여 **Supabase 로직은 제거하지 않고 스위칭 가능**한 구조로 남긴다. 

#### **해결**
- `config`의 상수(`DEMO_MODE`)로 데이터 레이어를 분기
  - `DEMO_MODE=true`: `IndexedDB(idb)` 사용
  - `DEMO_MODE=false`: 기존 Supabase 로직 유지

- 인증/게시글/댓글을 **IndexedDB 스토어로 마이그레이션**
  - 로그인: 데모 모드에서는 닉네임 기반 간소 로그인
  - 게시글/댓글: CRUD 및 권한 처리 로직을 로컬 DB에 맞게 재구성

- **schema.md 작성**
  - 스토어/인덱스/버전업(마이그레이션) 규칙을 문서로 기록해, “데이터 구조가 바뀌어도 유지보수 가능”하게 정리

- **데모 안내 배너**
  - 데모 데이터 리셋 버튼 제공(테스트/리뷰 시나리오를 빠르게 재현)

#### **결과**
- 외부 서비스 상태와 무관하게 **항상 동작하는 데모 확보**
- 데이터 구조 변경이 생겨도 `DB_VERSION` 업그레이드 규칙으로 안전하게 확장 가능

## 3. Vercel 배포 후 Reload 404 해결

#### **문제 상황**

SPA 라우팅 특성상 `/posts/123` 같은 딥링크에서 새로고침 시, 정적 파일로 인식되어 404 발생

#### **해결**

Vercel `rewrites` 설정으로 모든 경로를 index.html로 fallback

#### **결과**

딥링크 공유/새로고침에서도 페이지 정상 동작 → 데모 품질 개선
